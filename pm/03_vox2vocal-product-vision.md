## 비전 한 문장 (Vision Statement)

Vox2Vocal은 한 명의 개인 사용자가 자신의 목소리를 노래 안에서 들어보고, 목표 곡/구간 대비 pitch, note, 발성 상태를 안전하게 확인하며, 반복 실험을 통해 스스로 보컬 감각을 이해하도록 돕는 비상업적 개인 Voice to Vocal 학습 시스템이다.

## 대상 사용자 (Target Users)

현재 제품의 대상 사용자는 **프로젝트 소유자 본인인 단일 개인 사용자**다.

이 사용자는 다음 역할을 동시에 가진다.

- 앱 사용자: 앱 계정을 만들고 로그인해 본인 음성을 녹음/업로드하고 결과를 듣는다.
- 곡 관리자: 관리자 페이지에서 원하는 곡을 업로드하고 구간을 정의한다.
- 실험 운영자: 처리 결과, 실패 원인, 삭제, 알림, 접근 통제를 직접 확인한다.
- 학습자: 변환 preview, pitch/note 비교, 발성 참고 정보를 바탕으로 자기 목소리와 노래 습관을 이해한다.

현재 제품 비전의 대상이 아닌 사용자는 외부 학습자, 강사, 교육기관, AI 커버 제작자, 팬덤 콘텐츠 제작자, 다중 사용자 팀이다.

## 핵심 작업 (Core Job To Be Done)

사용자가 Vox2Vocal에게 기대하는 핵심 작업은 다음이다.

> 내가 원하는 곡의 특정 구간을 기준으로 내 목소리를 녹음하고, 내 목소리처럼 들리는 보컬 변환 preview를 들은 뒤, pitch/note/발성 참고 정보와 자기 평가를 통해 내가 어떻게 부르고 있는지 스스로 이해한다.

이 핵심 작업은 세 가지 사용자 결과로 나뉜다.

- 듣기: 내 목소리가 노래 형태로 변환되었을 때 실제로 어떻게 들리는지 확인한다.
- 비교하기: 원곡과 사용자 목소리의 pitch/note 흐름을 각각 신뢰 가능한 수준으로 분석하고, 목표 곡/구간과 어떻게 다른지 확인한다.
- 이해하기: 원곡 기준 진성/비성/두성/믹스보이스 등 발성학 기준을 정의하고, 가능하면 사용자 목소리도 같은 기준으로 참고 평가한다.

## 완성된 사용자 경험 (Completed User Experience)

완성된 Vox2Vocal에서 사용자는 먼저 앱 계정을 만들고, 자신의 개인정보와 알림 설정이 어떤 목적으로 쓰이는지 이해한 상태로 로그인한다. 사용자의 음원, 원본 음성, 변환 산출물, 분석 결과는 이 계정에 연결되어 관리되며, 시스템 밖으로 공유되거나 공개되지 않는다.

사용자는 앱과 분리된 관리자 페이지에서 자신이 실험하고 싶은 곡을 업로드하고, 곡 안에서 확인하고 싶은 구간을 정리한다. 곡별 출처, 권리 메모, 구간 정의는 기존 문서에서 정의한 수준을 유지한다. 제품은 곡 전체를 한 번에 완벽하게 처리하려 하기보다, 사용자가 선택한 구간을 중심으로 안정적인 실험 루프를 제공한다.

첫 안정 검증 구간은 너무 짧아서 목소리 정체성과 pitch/note 흐름을 판단하기 어렵거나, 너무 길어서 처리 실패와 디버깅 비용이 커지지 않아야 한다. 완성된 제품은 기본적으로 20~30초 구간을 안정 검증의 출발점으로 삼고, 발성 참고 정보까지 충분히 보려는 경우 30~45초 구간까지 확장할 수 있게 한다.

사용자는 앱에서 해당 곡/구간을 선택하고 본인 음성을 녹음하거나 업로드한다. 처리 중에는 상태를 확인할 수 있고, 완료/실패/삭제/보안 관련 중요한 변화는 push 알림으로 받을 수 있다.

처리가 완료되면 사용자는 앱 안에서만 변환 preview를 재생한다. preview는 외부 다운로드, 공유, 공개 URL이 아니라 개인 확인용으로 제공된다. 사용자는 preview가 내 목소리처럼 들리는지 1~5점 척도와 self-voice 평가 문항으로 평가하고, 원본 녹음과 비교해 자신의 목소리 특성을 확인한다.

결과 화면은 원곡 pitch/note와 사용자 목소리 pitch/note가 각각 95% 이상 분석된 경우를 신뢰 가능한 자기 점검 기준으로 보고, 목표 구간 대비 흐름을 이해할 수 있게 돕는다. 발성 정보는 원곡 기준 발성학 정의를 우선 제공하고, 사용자 목소리는 평가 가능한 경우에 한해 confidence 기반 참고 정보로 제공한다. 사용자는 한 번의 결과를 최종 답으로 받아들이지 않고, 다른 녹음, 다른 구간, 다른 곡으로 반복 실험하며 스스로 보컬 감각을 축적한다.

완성된 경험에서 중요한 것은 “공유할 만한 AI 커버를 만드는 것”이 아니라, 사용자가 안전한 개인 시스템 안에서 자기 목소리를 더 잘 듣고 이해하는 것이다.

## 노스스타 지표 (North Star Metric)

노스스타 지표는 **유효한 자기 목소리 preview 완료 세션 수 (Valid Self-voice Preview Sessions)**다.

유효한 자기 목소리 preview 완료 세션은 다음 조건을 만족해야 한다.

- 사용자가 직접 업로드한 곡/구간 또는 자신이 관리하는 곡/구간을 선택했다.
- 사용자 본인 음성을 입력했다.
- 시스템이 특정 구간에 대한 변환 preview를 생성했다.
- 사용자가 앱 안에서 preview를 기준 이상 재생했다.
- 사용자가 preview가 내 목소리처럼 들리는지 1~5점 척도로 평가했다.
- self-voice 평가는 자기 목소리 유사도, 발음/음색 자연스러움, 노래 표현 유지, 반복 학습 가치 기준을 포함했다.
- 4점 이상은 self-voice success 후보로 기록되고, 1~2점은 실패로 기록되며, 3점은 애매함 또는 구간별 재검토 대상으로 남는다.
- 실패 또는 애매함의 경우 내 목소리 아님, pitch 이상, timing 이상, 음색 손상, artifact, 발음/가사 문제, 과한 보정 등 실패 사유를 기록했다.
- 원곡과 사용자 목소리의 pitch/note 분석이 각각 95% 이상 또는 그에 준하는 신뢰 기준을 충족했다.
- 원곡 발성 기준이 정의되어 있고, 사용자 발성 참고 정보는 confidence와 함께 제공되었다.
- preview와 관련 데이터가 외부 공유/다운로드/공개 URL 없이 계정 내부에서만 접근되었다.

이 지표를 선택하는 이유는 제품의 핵심 가치가 사용자 수, 곡 수, 처리량이 아니라 **내 목소리 기반 preview를 실제로 듣고 자기 점검까지 이어지는 완결된 개인 학습 루프**에 있기 때문이다.

## 제품 원칙 (Product Principles)

- 개인 학습 우선 (Personal Learning First): 제품의 모든 판단은 외부 시장보다 단일 사용자의 학습 가치와 기술 검증을 우선한다.
- 단일 사용자 단순성 (Single-user Simplicity): 사용자는 한 명이며, 사용자/관리자/운영자 역할은 같은 개인이 수행한다.
- 본인 음성 원칙 (Own Voice Only): 처리 대상은 사용자 본인 음성으로 제한한다.
- 구간 우선 검증 (Section-first Validation): 여러 곡을 업로드할 수 있어도 완성된 학습 경험은 특정 구간 단위의 안정적인 반복 실험에서 시작한다.
- 안정 구간 길이 원칙 (Stable Segment Length): 첫 안정 검증은 20~30초 구간을 기본 출발점으로 삼고, 발성 참고까지 보려는 경우 30~45초 구간까지 확장한다.
- 앱 내부 통제 (Controlled In-app Access): 음원, 원본 음성, 변환 산출물, 분석 결과는 시스템 내부에서만 접근 가능해야 한다.
- 개인정보 목적 제한 (Purpose-limited Personal Data): 계정 정보와 알림 연락처는 인증, 보안, 처리 상태 안내, 개인 알림에 한정한다.
- Push 우선 알림 (Push-first Notification): 처리 완료, 실패, 삭제, 보안 관련 개인 알림은 push를 우선하고, push 실패 시 앱 내부 알림함과 작업 상태 화면을 정본 fallback으로 둔다.
- 분석 신뢰도 기준 (Analysis Reliability Bar): 원곡 pitch/note와 사용자 목소리 pitch/note는 각각 95% 이상 분석된 경우를 자기 점검 기준으로 삼는다.
- 참고형 발성 분석 (Confidence-based Vocal Guidance): 원곡은 진성/비성/두성/믹스보이스 등 발성학 기준으로 정의하고, 사용자 목소리는 평가 가능한 경우 confidence와 함께 참고 정보로 제공한다. 사용자 발성 경향은 confidence 0.85 이상에서 표시하고, 0.75~0.85는 추정/재녹음 권장으로, 0.75 미만은 라벨 숨김으로 처리한다.
- 반복 실험 가능성 (Repeatable Experimentation): 사용자는 다른 녹음, 다른 구간, 다른 곡으로 쉽게 다시 실험할 수 있어야 한다.
- 단일 변수 비교 (Single-variable Comparison): 시스템 개선을 위한 A/B 비교는 engine setting, take, section, prompt/config까지 허용하되, 한 번의 비교에서는 하나의 변수만 바꾼다.
- 분리된 경험 (Separated App and Admin Experience): 완성형에서도 앱과 관리자 페이지는 분리된 경험으로 유지한다.
- 개인 비상업 권리 원칙 (Personal Use Only, No External Use): 업로드 곡은 권리 확보 곡으로 간주하지 않고 `rights_not_cleared_personal_use_only`를 기본 상태로 둔다. 개인 비상업 학습/실험용 내부 자산으로만 쓰고, 외부 공유, 수익화, 배포, 모델 학습에는 쓰지 않는다.
- 제품화 유보 (Productization Deferred): 다중 사용자, 강사, 교육기관, 수익화는 개인 실험의 가치가 충분히 검증된 뒤 별도 판단한다.

## 되지 않을 것 (Anti-vision / Non-goals)

Vox2Vocal은 현재 단계에서 다음이 되지 않는다.

- 상업 서비스
- 강사/교육생 플랫폼
- 교육기관용 SaaS
- AI 커버 공개/공유 서비스
- 음원 배포 또는 판매 서비스
- 음원 또는 preview를 외부로 공유하는 서비스
- 팬덤 콘텐츠 제작 도구
- 다중 사용자 협업 시스템
- 타인 음성 또는 유명인 음성 변환 시스템
- 발성 진단을 확정적으로 내려주는 의료/전문 평가 도구
- 곡 전체를 빠르게 대량 처리하는 음악 제작 플랫폼
- 권리 확보가 불명확한 곡을 외부 공개, 수익화, 배포, 모델 학습에 사용하는 시스템

특히 산출물은 외부 공유나 공개 게시를 위한 콘텐츠가 아니라, 단일 사용자가 자기 목소리와 노래 상태를 이해하기 위한 개인 preview다.

## 결정된 기준 (Resolved Decisions)

### Self-voice 평가 기준 (Self-voice Evaluation Criteria)

Self-voice 평가는 "노래를 잘했는가"보다 "내 목소리처럼 들리는가"를 중심으로 기록한다. 점수는 절대 품질 등급이 아니라 반복 생성 결과를 비교하고 다음 실험 방향을 정하기 위한 개인 기준이다.

현재 단계에서는 시스템을 만들고 개선하는 것이 주요 목적이므로 단일 종합 점수만 받지 않고, 4개 세부 문항을 항상 기록한다. 종합 점수는 세부 문항의 가중 결과로 계산하거나 보조 표시로만 사용한다.

| 항목 | 질문 | 가중치 |
|---|---|---:|
| 자기 목소리 유사도 | 내 말소리/노래소리의 정체성이 유지되는가? | 40% |
| 발음/음색 자연스러움 | 발음, 호흡, 음색이 어색하거나 합성처럼 들리지 않는가? | 25% |
| 노래 표현 유지 | 멜로디, 리듬, 감정 표현이 원곡 의도와 맞는가? | 20% |
| 반복 학습 가치 | 다음 실험의 기준 샘플로 남길 만한가? | 15% |

자기 목소리 유사도가 3점 이하라면 전체 평균이 높아도 self-voice success 후보로 보지 않는다.

### 1~5점 판정 기준 (Rating Interpretation)

| 점수 | 의미 | 처리 |
|---:|---|---|
| 5 | 확실히 내 목소리처럼 들림 | 성공 샘플 |
| 4 | 일부 아쉬움은 있지만 내 목소리 성공 후보로 볼 수 있음 | success 후보 |
| 3 | 판단이 갈리거나 구간별로만 괜찮음 | `review_pending` |
| 2 | 대체로 내 목소리로 느껴지지 않음 | 실패 |
| 1 | 합성감, 타인 목소리, 심한 왜곡으로 명확히 실패 | 실패 |

3점은 성공률에 포함하지 않는다. 현재 단계에서는 시스템 개선이 주요 목적이므로 3점 `review_pending` 결과의 기본 다음 행동은 A/B 비교로 둔다. 비교 대상이 없거나 입력 품질 문제가 명확한 경우에만 재청취, 재녹음, 구간 재생성을 보조 행동으로 사용한다.

### A/B 비교 운영 기준 (A/B Comparison Operating Rules)

A/B 비교의 목적은 더 좋은 결과물을 고르는 것만이 아니라 어떤 조건이 self-voice quality를 개선하는지 학습하는 것이다. 따라서 비교 범위는 넓게 열어두되, 결과 해석이 가능하도록 한 번의 비교에서는 하나의 변수만 바꾼다.

| 비교 단위 | 허용 여부 | 우선순위 | 설명 |
|---|---:|---:|---|
| 엔진 설정 (Engine Setting) | 허용 | 높음 | pitch correction 강도, formant 보존, denoise, F0 추정기, synthesis mode 등을 비교한다. |
| 녹음 테이크 (Take) | 허용 | 높음 | 같은 구간을 다르게 녹음했을 때 입력 품질 차이가 결과에 미치는 영향을 확인한다. |
| 프롬프트/설정 묶음 (Prompt/Config) | 허용 | 중간 | prompt 기반 엔진 또는 config preset 차이를 비교한다. |
| 구간 (Section) | 허용 | 중간 | Intro, A멜로, Chorus 등 구간별 안정성을 확인하되, 시스템이 어느 정도 안정된 뒤 우선순위를 높인다. |
| 여러 변수 동시 변경 | 제한 | 낮음 | 원인 해석이 어렵기 때문에 `exploratory` 비교로만 기록한다. |

P0 기준 우선순위는 engine setting, take, prompt/config, section 순서로 둔다. section 비교는 다른 구간에서도 품질이 유지되는지 확인하는 확장 검증에 가깝다.

A/B 비교 결과에는 최소한 `experiment_id`, `baseline_artifact_id`, `candidate_artifact_id`, `variable_type`, `variable_diff`, 곡/구간/take/엔진 버전, config hash 또는 prompt version, self-voice 4개 문항 점수, 선호 결과, 실패 tag를 저장한다.

### 발성 용어와 노출 기준 (Vocal Terminology and Confidence Threshold)

발성 라벨은 해부학적 확정 판정이 아니라 보컬 교육에서 쓰는 지각적/음향적 라벨로 정의한다. 제품 문구는 "당신은 두성입니다"가 아니라 "두성적 특성이 감지됩니다"처럼 경향, 가능성, 비교 포인트 중심으로 표현한다.

발성 용어 체계는 제품/서비스 내부 정의 체계로 먼저 구축한다. 단, 임의로 확정하지 않고 내부 리서치를 통해 전문 자료를 조사한 뒤 정리한다. 내부 정의는 음성 산출 구조, 노래 학습 이론, 음향/측정 용어, 청각적/지각적 표현, 보컬 교육 현장 용어, 건강/장애/평가 용어를 분류 기준으로 삼는다.

기준 자료는 ASHA Voice Disorders Practice Portal, The Voice Foundation, NATS/Vocapedia, Estill Voice Training을 우선 참고한다. 현재 단계의 검토 절차는 전문가 승인으로 표현하지 않고, Codex/GPT를 활용한 `AI-assisted Internal Review Approval`로 둔다. 필요 시 음성언어치료사, 이비인후과/후두 전문의, 보컬 코치, 성악/실용음악 교육자의 검토로 보강하되, 그 전까지 의료/음성장애/건강 판단에 해당하는 용어는 `needs_human_expert_review` 상태로 남긴다.

| 용어 | 제품 내 정의 |
|---|---|
| 흉성 | 낮거나 중간 음역에서 두께감, 밀도, 말소리와 가까운 질감이 강한 발성 경향 |
| 두성 | 높은 음역에서 가볍고 위쪽 공명감이 느껴지며, 과도한 압력 없이 이어지는 발성 경향 |
| 믹스보이스 | 흉성적 밀도와 두성적 가벼움이 함께 나타나 음역 전환을 부드럽게 만드는 중간적 발성 경향 |
| 가성 | 성대 접촉이 상대적으로 약하고 공기감이 많으며, 진성보다 얇고 분리된 느낌의 발성 경향 |
| 진성 | 제품 내에서는 `modal voice / non-falsetto`에 가까운 일반적인 성대 접촉 기반 발성 |
| 비성 | 코 공명 또는 비강 쪽 울림이 두드러지는 음색 경향 |

사용자 발성 경향은 confidence 0.85 이상에서 표시한다. 0.75~0.85는 "추정" 또는 "다시 녹음 권장"으로만 표시하고, 0.75 미만은 발성 모드 라벨을 숨긴다. 원곡과 사용자 발성을 직접 비교하는 경우에는 confidence 0.90 이상을 권장한다.

발성 용어의 내부 검토 상태는 `draft`, `ai_reviewed`, `internal_approved`, `needs_human_expert_review`, `deprecated`로 관리한다. 각 용어는 한글/영어 용어, 분류, 내부 정의, 사용자에게 보여줄 표현, 보여주면 안 되는 표현, 측정 가능 신호, confidence 기준, 참고 자료, AI 리뷰 결과, 승인 상태를 함께 가진다.

### 알림과 개인정보 정책 위치 (Notification and Privacy Policy Placement)

알림은 `push_first_in_app_fallback`으로 운영한다. 기본 알림은 push이며, push 실패/거부/token 만료 시 앱 내부 알림함과 작업 상태 화면을 정본 fallback으로 둔다. 이메일 fallback은 기본 비활성으로 두고, 계정 보안, 삭제 요청, 장시간 실패 같은 중요 알림에만 `verified_email_opt_in_critical_only`로 허용한다.

Push payload에는 곡명, 음원 세부정보, 권리 맥락 등 민감 정보를 넣지 않고 "처리 완료", "확인 필요" 수준의 최소 정보만 담는다. 앱 사용자 알림과 관리자 운영 알림은 분리한다.

계정 정보와 알림 연락처의 보관 기간, 삭제, 수신 거부 기준은 제품 비전에서 기본값을 정하고, 이후 `Privacy & Data Retention Policy`를 정본으로 관리한다. `Data Inventory / Data Map`은 필드별 보관 기간과 삭제 trigger를 관리하고, `Admin Operations Runbook`은 실제 삭제/비활성화/token 폐기/backup 만료 절차를 관리한다. App/Admin PRD는 정책 본문을 중복 작성하지 않고 필요한 UI 요구사항만 참조한다.

| 데이터 | 기본 보관 기준 |
|---|---|
| 계정 기본 정보 | 계정 유지 기간 동안 보관 |
| 계정 삭제 요청 | 즉시 비활성화, token 폐기, 알림 중단 |
| 활성 DB 개인정보 | 삭제 요청 후 7일 이내 삭제 또는 익명화 |
| 이메일/SNS 계정 정보 | 계정 유지 또는 연결 해제 전까지 |
| 미인증 이메일/SNS 정보 | 30일 후 삭제 |
| Push token | 로그아웃, 앱 삭제 감지, 수신 거부 시 즉시 비활성화 |
| 비활성 push token | 90일 후 삭제 |
| 알림 수신 동의 기록 | 계정 유지 기간 + 삭제 후 1년, 최소 정보만 보관 |
| 수신 거부 기록 | 계정 유지 기간 동안 보관, 삭제 후에는 salted hash만 최대 1년 보관 |
| 인증/로그인 보안 로그 | 180일 |
| 관리자 행동 로그 | 1년 |
| 일반 앱 이벤트 로그 | 30~90일 |
| self-voice 평가 데이터 | 시스템 개선 목적상 1년 보관, 삭제 시 계정 식별자 제거 |
| 백업 데이터 | 최대 35일 rolling retention |
| 백업 내 삭제 예외 | 백업을 직접 수정하지 않고 만료로 삭제, 복원 시 삭제 요청 재적용 |
| 법적/보안 사고 hold | 개인 시스템에서는 원칙적으로 사용하지 않고, 필요 시 사유/만료일/담당자를 기록 |

삭제 요청이 들어오면 로그인 차단, access/refresh token 폐기, push token 비활성화, 알림 queue 제거, 활성 DB 개인정보 삭제 또는 익명화, 객체 저장소의 개인 산출물 삭제, 삭제 tombstone 기록, 백업 만료 대기, 백업 복원 시 tombstone 재적용 순서로 처리한다. 삭제와 저장 매체 폐기는 NIST SP 800-88 Rev.2의 media sanitization 개념을 참고한다.

### 곡 업로드 권리 상태 (Uploaded Song Rights Status)

업로드 곡의 기본 권리 상태는 `rights_not_cleared_personal_use_only`로 둔다. `personal_use_only`만 사용하면 개인 사용이라는 이유로 권리 문제가 정리된 것처럼 보일 수 있으므로 사용하지 않는다.

기본 정책 라벨은 다음과 같다.

```text
rights.status = rights_not_cleared
rights.allowed_use = personal_learning_experiment_only
rights.asset_scope = internal_only
rights.external_distribution = prohibited
rights.sale_or_monetization = prohibited
rights.model_training = prohibited
```

권리/출처 메모의 정본은 후속 `Rights and Source Register` 또는 `Admin Song Upload and Rights PRD`에서 관리한다. 제품 비전은 원칙만 고정하고, 곡별 출처, 권리 메모, 사용 목적, 금지 사용, checksum, upload owner, section 정의, 삭제 상태는 해당 정본에서 관리한다.
