# 제품 전략 (Product Strategy)

## 전략 요약 (Strategy Summary)

Vox2Vocal의 현재 전략은 상업 서비스, 강사/교육생 플랫폼, AI 커버 공유 서비스가 아니라 **단일 개인 사용자를 위한 비상업적 Voice to Vocal 학습/실험 시스템**으로 집중하는 것이다.

제품은 한 명의 사용자가 앱 계정을 생성하고, 관리자 페이지에서 원하는 곡을 업로드한 뒤, 본인 음성을 녹음/업로드하고, 특정 구간의 보컬 변환 preview를 앱 안에서 들어보며 pitch, note, 발성 상태를 스스로 확인하는 경험을 우선한다.

전략의 중심은 사용자 수 확장이나 곡 카탈로그 확대가 아니라, 다음 질문에 답하는 것이다.

- 내 목소리 기반의 변환 결과가 실제로 내 목소리처럼 들리는가?
- pitch/note 분석이 목표 구간과 비교 가능한 수준으로 제공되는가?
- 발성 추정이 자기 점검에 참고 가능한 형태로 제공되는가?
- 관리자 페이지에서 내가 원하는 곡을 올리고, 구간 단위로 안정적으로 실험할 수 있는가?
- 계정 기반 접근, 개인정보/알림, 외부 공유 차단, 삭제가 개인 시스템 수준에서 안전하게 동작하는가?

## 첫 타깃 세그먼트 (First Target Segment)

첫 타깃은 **프로젝트 소유자 본인인 단일 개인 사용자**다.

이 세그먼트를 먼저 선택하는 이유는 다음과 같다.

- 현재 제품의 목적은 시장 진입이나 다중 사용자 운영이 아니라 개인 학습과 기술 검증이다.
- 단일 사용자 전제에서는 강사/교육생 권한, 리뷰 워크플로우, 기관 운영 기능을 제외하고 핵심 voice-to-vocal 경험에 집중할 수 있다.
- 개인정보, 음원, 원본 음성, 산출물 접근 범위를 계정 1개 기준으로 강하게 통제할 수 있다.
- 관리자 페이지 곡 업로드, 구간 정의, 본인 음성 처리, preview 재생, 자기 평가를 한 사람의 end-to-end 흐름으로 검증할 수 있다.

현재 첫 타깃이 아닌 대상은 다음과 같다.

- 외부 음악 학습자
- 강사 또는 교육기관
- AI 커버 제작자
- 음원 공유/배포 사용자
- 팬덤 기반 콘텐츠 제작자
- 다중 사용자 팀 또는 운영 조직

## 핵심 문제 (Core Problem)

현재 핵심 문제는 “여러 사용자를 위한 보컬 교육 서비스를 어떻게 만들 것인가”가 아니다.

먼저 해결할 문제는 **내 목소리가 노래 안에서 어떻게 들리는지, 목표 곡/구간 대비 pitch와 발성 상태가 어떤지, 특정 구간 단위로 반복 실험 가능한 개인 학습 루프를 만들 수 있는지**다.

구체적으로는 다음 문제가 있다.

- 내 원본 음성이 보컬 변환 결과에서 얼마나 자연스럽게 유지되는지 직접 확인하기 어렵다.
- 목표 곡/구간 대비 내 pitch와 note 흐름이 어느 정도 맞는지 확인하기 어렵다.
- 진성, 비성, 두성 등 발성 상태는 주관적으로 느끼기 쉬워 자기 점검 근거가 부족하다.
- 곡 전체 처리보다 특정 구간에서 먼저 안정적으로 성공시키는 검증 루프가 필요하다.
- 개인 계정, 알림, 음원/음성/산출물 접근 차단, 삭제 같은 안전 장치가 없으면 개인 실험이라도 리스크가 커진다.

## 차별화 / 포지셔닝 (Differentiation / Positioning)

Vox2Vocal의 현재 포지셔닝은 **개인 계정 기반 Voice to Vocal 자기 점검 시스템**이다.

비교 기준은 다음과 같다.

- AI 커버 서비스: 다른 사람에게 들려주거나 공유할 완성 콘텐츠 생성이 중심이다.
- 일반 보컬 분석 앱: pitch 점수나 녹음 분석이 중심이다.
- Vox2Vocal: 내 목소리처럼 들리는 변환 preview와 pitch/note/발성 참고 정보를 하나의 개인 실험 루프로 묶는 것이 중심이다.

차별화는 다음 조합에서 나온다.

- 단일 사용자 기준으로 복잡도를 줄인 end-to-end voice-to-vocal pipeline
- 내가 원하는 곡을 관리자 페이지에서 업로드하고 구간 단위로 검증하는 흐름
- 본인 음성만 사용하는 자기 목소리 중심 실험
- 앱 계정 기반 접근과 시스템 외부 공유 차단
- 개인정보 기반 개인 알림을 통한 처리 상태 안내
- 외부 제품화 전에 기술 가능성과 자기 학습 가치를 먼저 검증하는 좁은 전략

## 전략적 선택과 비선택 (Strategic Choices and Non-choices)

### 전략적 선택 (Strategic Choices)

- 사용자는 한 명으로 고정한다.
- 앱 계정을 생성하고, 해당 계정에 음원, 원본 음성, 변환 산출물, 분석 결과를 연결한다.
- 개인정보는 인증, 보안, 처리 상태 안내, 개인 알림 목적으로 제한 사용한다.
- 곡 업로드는 관리자 페이지에서 개인 소유자 본인이 수행한다.
- 원하는 곡들을 업로드할 수 있지만, 검증 단위는 곡 전체보다 특정 구간을 우선한다.
- 첫 성공 기준은 곡 수, 사용자 수, 공유 수가 아니라 “내 목소리처럼 들리는 preview를 안정적으로 만들 수 있는가”다.
- pitch/note 분석은 자기 점검 가능한 비교 정보로 제공하는 것을 우선한다.
- 발성 분석은 확정 판정이 아니라 confidence 기반 참고 정보로 다룬다.
- 음원, 원본 음성, 산출물은 앱/시스템 내부에서만 접근 가능하게 한다.
- 처리 완료, 실패, 삭제, 보안 관련 상태는 개인 알림 대상으로 본다.

### 전략적 비선택 (Strategic Non-choices)

- 강사/교육생 분리 모델을 만들지 않는다.
- 외부 사용자를 모집하지 않는다.
- 교육기관, B2B, B2C 수익화를 현재 전략에 포함하지 않는다.
- AI 커버 공개, 음원 공유, 산출물 다운로드, 공개 게시를 목표로 삼지 않는다.
- 다중 사용자 권한, 강사 리뷰, 학생 관리, 기관 운영 기능을 현재 전략에 포함하지 않는다.
- 유명 상용곡 카탈로그 확대를 성공 기준으로 삼지 않는다.
- 곡 전체 처리, full-song 완성도, 빠른 대량 처리보다 구간 단위 안정성을 먼저 본다.
- 발성 분석을 절대적 진단이나 확정 평가로 포지셔닝하지 않는다.

## 제품 원칙 (Product Principles)

- 개인 학습 우선 (Personal Learning First): 모든 판단은 외부 시장보다 개인 학습 가치와 기술 검증에 맞춘다.
- 단일 사용자 단순성 (Single-user Simplicity): 권한, 리뷰, 운영 흐름은 한 명의 사용자/관리자/운영자 기준으로 단순화한다.
- 본인 음성 원칙 (Own Voice Only): 처리 대상은 사용자 본인 음성으로 제한한다.
- 구간 우선 검증 (Section-first Validation): 여러 곡을 업로드할 수 있어도 초기 검증은 특정 구간의 안정성을 우선한다.
- 앱 내부 통제 (Controlled In-app Access): 음원, 원본 음성, 산출물은 외부 공유 없이 앱/시스템 안에서만 접근하게 한다.
- 개인정보 목적 제한 (Purpose-limited Personal Data): 계정 정보와 알림 연락처는 인증, 보안, 처리 안내, 개인 알림에 한정한다.
- 참고형 분석 (Confidence-based Guidance): pitch/note/발성 분석은 자기 점검을 돕는 정보이며 확정 진단처럼 다루지 않는다.
- 제품화 유보 (Productization Deferred): 다중 사용자, 강사, 교육기관, 수익화는 개인 실험의 가치가 검증된 이후 별도 판단한다.

## 핵심 지표 (Key Metrics)

### 자기 목소리 가치 지표 (Self-voice Value Metrics)

- Preview 생성 성공률: 선택한 구간에서 preview가 생성된 비율
- Self-voice 만족도: preview가 내 목소리처럼 들린다고 판단한 비율
- Preview 재생 완료율: 기준 이상 preview를 실제로 들은 비율
- 재시도율: 결과를 듣고 다시 녹음하거나 다른 구간/곡으로 반복 실험한 비율

### 분석 가치 지표 (Analysis Value Metrics)

- Pitch 비교 가능률: 내 pitch와 목표 구간 pitch를 비교 가능한 형태로 받은 비율
- Note sequence 유효성: 목표 note 흐름과 사용자 입력 분석 결과가 자기 점검에 도움이 된다고 판단한 비율
- 발성 참고 유효성: 진성/비성/두성 등 발성 추정 결과가 참고 가능하다고 판단한 비율
- Confidence 표시율: 불확실한 분석 결과에 confidence 또는 불확실성 표시가 포함된 비율

### 운영/안전 지표 (Operations and Safety Metrics)

- 곡/구간 처리 성공률: 관리자 업로드 곡의 특정 구간 처리가 성공한 비율
- 처리 실패 복구율: 실패 후 재시도 또는 원인 확인이 가능했던 비율
- 외부 접근 차단율: 음원, 원본 음성, 산출물에 대한 외부 공유/다운로드/공개 URL이 차단된 비율
- 알림 정확도: 처리 완료/실패/삭제/보안 관련 개인 알림이 정확히 발송되거나 발송 대기 상태로 기록된 비율
- 삭제 처리 성공률: 원본 음성/산출물 삭제가 정상 처리된 비율

## 검증 필요 영역 (Validation Gaps)

- 내 목소리처럼 들린다는 기준을 어떤 평가 척도로 기록할 것인가?
- 여러 곡을 업로드할 때 곡별 metadata, 구간 정의, 권리/출처 기록을 어느 수준까지 관리할 것인가?
- 첫 검증 구간은 길이를 어느 정도로 제한해야 안정성과 학습 가치가 균형을 이루는가?
- pitch/note 분석은 어떤 최소 정확도 또는 confidence 기준을 넘으면 자기 점검용으로 충분한가?
- 발성 분석은 어떤 정보까지 제공해야 도움이 되고, 어디부터는 과도한 판정이 되는가?
- 개인정보 기반 알림은 이메일, SNS, push 중 무엇을 우선할 것인가?
- 개인 알림을 위해 어떤 동의, 수신 설정, 보관 기간, 삭제 정책이 필요한가?
- 비상업 개인 사용이어도 저작권/권리 리스크를 낮추기 위해 곡 업로드 시 어떤 최소 출처 기록이 필요한가?
- 앱과 관리자 페이지를 분리할지, 단일 개인 콘솔로 시작할지 전략적으로 정해야 한다.
