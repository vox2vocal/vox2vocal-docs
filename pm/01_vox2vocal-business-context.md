## 사업 목표 (Business Goals)

Vox2Vocal의 현재 목표는 상업 서비스나 다중 사용자 교육 플랫폼을 만드는 것이 아니라, **개인 사용자가 자기 목소리 기반의 보컬 변환 결과를 듣고 음정, 발성, 표현을 스스로 이해하기 위한 비상업적 개인 학습/실험 시스템**을 만드는 것이다.

현재 전제에서는 강사와 교육생을 분리하지 않는다. 사용자는 한 명이며, 사용자/관리자/운영자는 모두 동일한 개인이다.

이 단계의 핵심 목표는 다음과 같다.

- 내 목소리를 보정/생성한 노래 결과가 실제로 "내 목소리처럼 들리는지" 확인한다.
- 내 현재 음정이 목표 곡/구간과 얼마나 맞는지 확인한다.
- 진성, 비성, 두성 등 발성 상태를 분석하거나 추정할 수 있는 가능성을 검토한다.
- 전체 상용 서비스가 아니라 개인 학습과 기술 검증에 필요한 최소 시스템 구조를 만든다.
- 내 계정을 앱에서 생성하고, 계정 기반 접근으로 음원, 음성, 산출물이 시스템 외부로 노출되지 않도록 통제한다.
- 계정 생성 과정에서 수집한 개인정보는 인증, 보안, 처리 상태 안내, 개인 알림 목적으로만 제한적으로 사용한다.

## 시장 / 고객 / 구매자 (Market / Customer / Buyer)

### 시장 (Market)

현재 단계에서는 시장 진입을 목표로 하지 않는다. 참고 시장은 보컬 학습, 취미 음악 학습, AI 보컬 변환, pitch/note 분석 도구 시장이지만, 제품 의사결정은 외부 고객 획득이나 수익화가 아니라 개인 학습 가치와 기술 검증을 기준으로 한다.

### 사용자 (User)

- 단일 개인 사용자
- 본인 목소리로 노래 변환 결과를 듣고 싶은 사용자
- 본인 음정, 발성, 표현 상태를 확인하고 싶은 사용자
- 앱 계정을 생성하고 개인정보 기반의 개인 알림을 받을 수 있는 사용자
- 관리자 페이지에서 원하는 곡들을 업로드하고 실행, 검토, 삭제까지 직접 관리하는 사용자

### 고객 (Customer)

현재 고객은 외부 고객이 아니라 프로젝트 소유자 본인이다. 강사, 교육기관, 일반 학습자, 외부 운영자는 현재 범위에서 제외한다.

### 구매자 (Buyer)

현재 구매자는 없다. 수익 창출, 유료 구독, 기관 판매, B2B/B2C 판매는 현재 목표가 아니다.

## 가치 교환 (Value Exchange)

현재 단계의 가치 교환은 돈을 받고 서비스를 제공하는 구조가 아니라, 개인 사용자가 시간과 개발 비용을 투자해 다음 가치를 얻는 구조다.

### 사용자가 얻는 가치 (User Value)

- 내 목소리가 노래 형태로 변환되었을 때 어떻게 들리는지 직접 확인한다.
- 원본 녹음과 변환 산출물을 비교하며 내 목소리의 특성을 이해한다.
- pitch, note sequence, 발성 추정 결과를 통해 연습 방향을 잡는다.
- 곡/구간 단위로 반복 실험하며 어떤 엔진 구성이 개인 학습에 유효한지 확인한다.
- 앱 계정으로 접근을 제한하고, 외부 공유 없이 개인 시스템 안에서 안전하게 실험한다.
- 처리 완료, 실패, 삭제, 보안 관련 상태를 개인 알림으로 받을 수 있다.

### 시스템이 얻는 가치 (System Value)

- 단일 사용자 환경에서 voice-to-vocal pipeline의 end-to-end 가능성을 검증한다.
- 관리자 페이지를 통한 곡 업로드, 구간 정의, 본인 음성 입력, 처리, 프리뷰 재생, 결과 평가의 최소 흐름을 검증한다.
- 향후 제품화 여부를 판단할 수 있는 기술/품질/운영 데이터를 축적한다.

## 수익 모델 / 성장 방식 (Revenue Model / Growth Motion)

현재 수익 모델은 없다.

현재 단계에서 하지 않는 것은 다음과 같다.

- 유료 구독
- 곡/세션 판매
- 강사용 학생 관리
- 교육기관 판매
- 외부 사용자 모집
- 음원/산출물 배포
- AI 커버 공개 또는 공유

성장 방식도 현재는 사용자 수 확대가 아니라 개인 학습/기술 검증의 깊이를 늘리는 방식으로 본다.

- 한 명의 사용자가 반복적으로 사용할 수 있는지 확인한다.
- 관리자 페이지에서 내가 원하는 곡들을 업로드하되, 검증은 곡 전체가 아니라 특정 구간 단위로 안정적으로 동작하는지 확인한다.
- 내 목소리처럼 들리는 결과를 만들 수 있는지 확인한다.
- pitch/note/발성 분석이 실제 자기 점검에 도움이 되는지 확인한다.
- 이후 제품화 가능성이 보일 때만 다중 사용자, 강사, 교육기관, 수익화 방향을 별도 검토한다.

## 전략 제약 (Strategic Constraints)

- 단일 사용자 제약: 현재 사용자는 한 명이며, 권한 모델은 다중 사용자 협업보다 개인 소유자 중심으로 단순화한다.
- 계정 기반 접근 제약: 사용자는 앱 계정을 생성해 로그인하며, 음원, 원본 음성, 변환 산출물, 분석 결과는 해당 계정에 연결된 개인 데이터로 관리한다.
- 비상업 제약: 현재 목적은 개인 학습/실험이며 수익 창출, 외부 판매, 홍보, 공개 배포를 하지 않는다.
- 외부 접근 차단: 음원, 원본 음성, 변환 산출물은 시스템 내부에서만 접근 가능해야 하며 외부 공유, 다운로드, 공개 URL, 검색 노출을 기본 차단한다.
- 곡 업로드 주체: 곡 업로드는 개인 소유자 본인이 관리자 페이지에서 수행한다. 외부 사용자가 곡을 업로드하는 구조는 현재 범위가 아니다.
- 개인정보/알림 제약: 계정 생성 시 수집한 개인정보는 인증, 계정 보안, 처리 상태 안내, 개인 알림 목적에 한정한다. 추후 알림을 보낼 수 있도록 보관하되, 목적 외 사용이나 제3자 제공은 현재 범위에서 제외한다.
- 저작권/권리 제약: 비상업/개인 학습 목적이라도 저작권 리스크가 자동으로 사라지는 것은 아니다. 권리 출처가 불명확한 곡은 공개, 공유, 배포, 수익화, 외부 테스트에 사용하지 않는다.
- 처리 범위 제약: 전체 곡보다 특정 구간 단위 처리와 재생을 우선한다.
- 음성 권리 제약: 사용자 본인 음성만 허용한다. 타인의 음성, 유명인 음성, 제3자 보이스 모델은 현재 범위에서 제외한다.
- 보안/개인정보 제약: 원본 음성, 변환 산출물, 계정 정보, 분석 결과는 민감 데이터로 다룬다.
- 기술 제약: pitch extraction, note sequence estimation, voice conversion/synthesis, audio segmentation, playback control의 안정성이 핵심이다.
- 운영 제약: 별도 운영팀 없이 개인 개발자가 개발, 업로드, 실행, 검토, 삭제를 모두 담당한다.

## 성공 지표 (Business Success Indicators)

현재 단계의 성공 지표는 사업 매출이 아니라 개인 학습 가치와 기술 검증 지표다.

- 내 목소리처럼 들린다고 판단한 preview 비율
- preview를 실제로 끝까지 또는 기준 이상 재생한 비율
- 원본 녹음 대비 변환 결과가 학습 점검에 도움이 된다고 판단한 횟수
- pitch/note 분석이 목표 구간과 비교 가능한 형태로 제공된 비율
- 발성 추정 결과가 자기 점검에 참고 가능하다고 판단한 비율
- 곡/구간 처리 성공률
- 처리 실패율과 재시도 필요 횟수
- 외부 접근, 다운로드, 공유가 차단된 상태로 유지된 비율
- 처리 완료/실패/삭제 등 개인 알림이 정확하게 발송되거나 발송 대기 상태로 기록된 비율
- 원본 음성/산출물 삭제 요청 또는 수동 삭제가 정상 처리된 비율

## 근거와 가정 (Evidence and Assumptions)

### 확인된 근거 (Evidence)

- 현재 사용자는 한 명이며, 강사/교육생 분리를 하지 않는다.
- 현재 목적은 비상업적인 개인 학습/실험이다.
- 사용자는 앱 계정을 생성하고, 이를 통해 수집한 개인정보로 추후 개인 알림을 받을 예정이다.
- 사용자는 관리자 페이지에서 원하는 곡들을 직접 업로드할 예정이다.
- 가장 중요한 경험은 내 목소리를 보정/생성한 노래 결과를 들어보는 것이다.
- 다음 관심사는 현재 음정이 목표 곡/구간에 맞는지 확인하는 것이다.
- 그 다음 관심사는 진성, 비성, 두성 등 발성 상태를 확인하는 것이다.
- 음원과 산출물은 시스템 외부에서 접근할 수 없게 해야 한다.

### 가정 (Assumptions)

- 단일 사용자 전제에서는 복잡한 강사/교육생 권한, 리뷰 워크플로우, 기관 운영 기능이 초기에는 필요하지 않다.
- 단일 사용자 전제라도 계정, 인증, 개인정보 보관, 알림 동의, 알림 수신 설정은 필요하다.
- 개인 학습 목적이라도 음원 권리, 원본 음성 보관, 산출물 접근 통제는 제품 신뢰와 안전의 핵심이다.
- 여러 곡 업로드를 허용하더라도, 초기 기술 검증은 곡 전체보다 특정 구간부터 안정적으로 성공시키는 편이 유리하다.
- 발성 분석은 pitch/note 분석보다 불확실성이 높을 수 있으므로, 초기에는 confidence와 참고 정보 중심으로 다루는 것이 안전하다.
- 현재 단계의 산출물은 외부 공유용 콘텐츠가 아니라 개인 확인용 preview로 보는 것이 맞다.

## 사업 리스크 (Business Risks)

- 권리 리스크: 비상업/개인 학습 목적이라도 저작권 문제가 완전히 면책된다고 볼 수 없다. 특히 외부 공유, 공개 URL, 다운로드, 수익화, 제3자 제공으로 이어지면 리스크가 커진다.
- 개인정보/알림 리스크: 단일 사용자라도 계정 정보와 알림 연락처를 수집하면 개인정보 보호, 보관 기간, 알림 동의, 수신 거부, 오발송 방지 기준이 필요하다.
- 범위 과대화 리스크: 강사, 교육생, 관리자, 기관, 수익화, 외부 업로드까지 동시에 고려하면 개인 학습 시스템이라는 중심이 다시 흔들릴 수 있다.
- 품질 리스크: 결과가 내 목소리처럼 들리지 않으면 핵심 가치가 약해진다.
- 분석 신뢰 리스크: pitch/note/발성 분석이 부정확하면 잘못된 자기 판단으로 이어질 수 있다.
- 보안 리스크: 원본 음성과 산출물이 외부에 노출되면 개인 음성 데이터와 음원 사용 리스크가 함께 발생한다.
- 운영 리스크: 개인 개발자가 개발, 데이터 관리, 권리 판단, 보안, 삭제를 모두 담당하므로 누락 가능성이 있다.
- 제품화 착시 리스크: 개인 실험에서 성공한 흐름이 다중 사용자/상업 서비스에도 그대로 맞을 것이라고 가정하면 위험하다.
